# 工作流 v0.5 实现状态

更新：2026-09-06。v0.5 已合入主分支 `main`，当前服务从主项目启动。[v0.6 视觉独立转换设计](workflow-v0.6.md) 已记录，执行器尚未迁移。

## 已实现

- `Pipeline.S2`：一次全书 type 决策，由程序应用 KEEP / EXCLUDE；原文中的 OCR 疑点留给转换处理。
- `Pipeline.S3/S4`：目录、标题索引与少量正文形成简短配置；公共模板固定，作者编号显式保留，不要求前置整书语义树。
- `pageflow.plan_pages`：按 `pages_per_task` 分配各页全部保留 block；最后一批允许不足设定页数。输入规模由页数控制，应用不再设置上下文或输出 token 上限。
- `pageflow.convert_pages`：所属 JSON 和原始 PDF 区域图像直接转换、纠错；需要时查询前后一页全部保留 block；邻页只读。默认无独立逐批或边界审查，`review_mode=all` 才追加独立审查。
- `pageflow.render_pages` 与 `Pipeline.S7`：按顺序继承环境栈，支持跨批 proof 和部分公式，统一生成 TeX 并调用 PATH 中的 XeLaTeX。错误只交给关联批次，每批默认两轮自动修复；手动恢复可为耗尽批次追加两轮机会，累计次数与实际用量保留。
- 输入与内容哈希校验、成功批次和候选结果恢复、局部修复记录、真实调用账本。修复后的最终片段以 S7 产物为准，最终报告区分转换时核对与独立审查。
- 面板可配置每批页数、并发、审查模式和连接等待时间；显示逐批已保存的结果。暂停会等待在途请求落盘，停止后续派发；恢复可调整并发。
- 官方订阅请求提交时保存上游任务及 turn 标识，未知请求先查询，已完成响应从原请求取回后进入正常校验，不重复计数。缺少句柄时保留未知状态；只有明确授权重试后才重新请求，旧账本及用量保留。自定义 HTTP 服务结果未知时继续保留未知，不假设支持恢复。

S0–S8 是程序检查点；S4、S5、S8 无模型请求。精简顺序见 [工作流](workflow.md)，机器契约已同步至 [0.5](workflow.contract.json)。

## 验证与边界

程序回归 **90 项通过**。Wang 完整 45 页真实流程已在第 8 修订通过 S0–S8：23 批转换、804 个保留块、138 个显式编号，最终 TeX 两遍编译通过，输出 52 页 PDF。46 次应用层 LLM 调用和所有中断／未知状态照实保留，新增 MinerU 提交 0。没有人工编辑论文转换片段。详见 [验证记录](validation-v0.5.md)。

真实联调修复了编号与图资源误判、TeX 换行分词、编译缺字验收、多行来源定位、指定批次重跑和跨修订恢复。独立缺字问题可并行修复，环境依赖修复仍按顺序处理。末页邮箱未进入解析 JSON 是已确认的解析局限，当前没有补造来源块。

实现不会用覆盖率或编译通过宣称数学保真。目录与正文标题冲突会明确停止并保留来源；不猜测目录正确性。原图覆盖保留 block 的区域，不能证明解析器未遗漏区域之外的正文。

## 启动与复用解析

正常安装与启动见 README。隔离工作树可复用已有 Python 环境，但强制从当前工作树导入代码：

```powershell
pwsh -File scripts/start.ps1 -Port 8766 -PythonExecutable D:/Hanako/Projects/BookAnalyst/.venv/Scripts/python.exe
```

跨工作树导入真实解析使用 `scripts/import_parse_cache.py --source-workspace <原工作树> --run-id <已有运行ID>`。程序以只读方式打开来源数据库，校验 S0/S1 的清单与全部文件哈希，只导入解析；不会把旧语义分析和转换当作新版产物。目标必须已登记相同 PDF。后续运行选择返回的 `cached_run_id`。
