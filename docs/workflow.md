# BookAnalyst 工作流 v0.5

更新：2026-09-06。此文是新版执行标准：按用户指定页数分配全部保留 block，转换时直接核对原图、修正识别错误并生成 TeX。恢复数学内容、标题架构和作者编号；页码、页眉及版面位置仅用于定位，不还原原书排版。

当前主分支与服务已实现 v0.5，并使用独立运行验证 Wang 论文。后续改造采用 [v0.6 视觉独立转换工作流](workflow-v0.6.md)，该新版尚未实现。实现进度见 [实现状态](implementation.md)。供应商登录和 API 配置见独立的 [供应商配置](llm-providers.md)，不作为处理阶段。

## 运行设置

| 设置 | 作用 |
| --- | --- |
| `pages_per_task` | 每个转换任务拥有几页的正文，用户指定正整数。首次测试可从 2 页开始，这不是模型容量推算出的最优值。 |
| `llm_concurrency` | 同时执行几个 LLM 请求，默认 2，可调整。可以是同一模型的多个并发实例。 |
| `review_mode` | 默认 `on_demand`：程序检查后只对具体问题追加 LLM 处理；可选 `all`：每批追加一次独立内容审查。 |

模型通过已有连接配置选择。LLM 总请求数默认不限；实际请求、重试和用量照实记录，不因恢复运行清零。

## 执行顺序与成员

| 步骤 | 执行者 | 输入 → 动作 → 输出 |
| --- | --- | --- |
| 1. 解析与聚合 | 程序、MinerU | PDF → 程序依 MinerU 接口上限粗分块，MinerU 解析，程序聚合 → 带物理页索引、block ID、原始类型及坐标的 JSON。已有完整解析直接复用。 |
| 2. 全书设置 | 程序、分析 LLM | 类型清单、目录和少量正文 → 确定统一忽略类型、标题层级及编号方式 → 一份简短的全书配置。 |
| 3. 分配任务 | 程序 | 过滤后的 JSON、`pages_per_task` → 按连续物理页分组 → 每批所属的全部 block 和可查询的前后邻页范围。无需 LLM 分组。 |
| 4. 并行转换 | 转换 LLM、程序 | 本批全部 block、对应原图、全书配置 → 同一次转换中识别数学环境、修正符号并生成统一 TeX → 正文片段、来源映射、实际修正记录和简短边界说明。 |
| 5. 合并与编译 | 程序；有具体问题时调用 LLM | 各批结果 → 按来源顺序合并、处理续接、统一导言区并编译 → TeX 工程、PDF 和实际处理记录。 |

### 1. 解析与聚合

MinerU 的提交分块与 LLM 的转换分组分别设置。转换批次不再触发 MinerU 请求。

原始 PDF 和 MinerU JSON 保持不变。程序检查解析页是否齐全、来源 ID 是否重复、资源是否可用，保留 JSON 已有的阅读顺序。物理页索引用于分配任务，不使用书上印刷的页码。

### 2. 全书设置

先由程序列出所有 MinerU box type 及数量，分析 LLM 一次决定各类型 KEEP 或 EXCLUDE，程序统一应用。例如可以统一排除 `header`、`page_number`；不能确定的类型保留。已排除内容不再送给转换 LLM。脚注、参考文献、图表及说明属于作者内容，应予保留。

随后，分析 LLM 根据目录、标题和少量代表性正文，确定文档类别、标题层级、常用数学环境及作者编号方式。优先利用原目录，没有目录也允许继续转换。材料不足时保留作者显式编号，不能先猜一套计数规则。

环境写法由公共模板固定；模型不各自定义导言区、宏和排版风格。原目录用于最终核对正文标题，转换中发现的编号或标题冲突集中反馈。此处不逐块分类，不预先建立整书语义树，也不提前修完整书的符号。

### 3. 按页分配与邻页查询

以 `pages_per_task=2` 为例：第一页至第二页属于任务 A，第三页至第四页属于任务 B，依次类推；最后一批可以不足两页。每批初次请求包含：

- 这些页内全部 KEEP block，保留 ID、顺序、类型和原文；不按 token 目标再挑选部分正文。
- 这些页保留 block 所在区域的原始 PDF 图像，供同一次转换核对数学符号；不重复发送独立逐块小图。
- 简短的全书设置和统一输出约定。

转换 LLM 必要时可以查询本批起始页之前一页、结束页之后一页的全部 KEEP block。邻页按需返回，不默认重复附带；书首、书尾超出范围时返回空。需要看符号时，可取同一邻页的原图。

查询由程序读取已保存的 JSON 或渲染原图，不重新解析。查询结果会增加实际模型上下文和交互开销，计入真实用量。邻页内容只供参考，不能在本批输出中重复生成。

输入规模由每批页数控制，应用不设置上下文容量门槛，也不设置输出 token 上限。token 估算仅用于用量记录，不阻塞请求。若上游实际拒绝输入或截断输出，保留失败状态，不能静默截断正文或声称已经处理完整。

### 4. 转换、修正与跨批次内容

转换 LLM 直接对照本批 JSON 和原图完成工作，不先单独转录图像、不登记疑点、也不先做一轮逐页符号修复。可以纠正解析错误，不能依据数学常识改写作者的论证或结论。原图确实无法辨认时，保留原文并指出具体位置。

输出保持精简：TeX 正文片段、block 来源映射、发生过的修正及其原图依据，以及批次首尾的续接说明。没有改动的正文无需附解释。标题和环境使用共同写法，作者编号交给公共配置统一处理。

分页只是任务边界。段落、公式或证明跨批次时，模型标明“承接上一批”“本批开始”或“延续下一批”，不能为使单批代码独立编译而擅自补齐内容或关闭环境。每个来源 block 的内容仅由所属批次输出一次。

前后一页未必足以确定一个很长的证明从何处开始。此时允许先输出承接片段；程序合并时沿批次顺序继承尚未结束的环境。只有相邻结果无法对接时，才把两侧片段和必要原文一起交给 LLM 处理，不把整章反复送给所有转换任务。

### 5. 合并、检查与交付

程序对每批检查：输出格式、所属 block 是否遗漏或重复、是否输出了邻页内容，以及是否夹带未经允许的导言区或排版命令。图表可以保留原始资源；图中已有内容不强制重复输出 OCR 文字。跨批次公式和环境在合并后检查，不要求每批分别独立编译。

所有批次完成后，程序按来源顺序合并，统一渲染标题、数学环境和编号，核对目录标题及已记录的边界，再调用本机 TeX 环境编译。缺字视为编译错误，不能接受静默漏符号的 PDF；来源映射包含 block 内换行，以真实 TeX 行号定位。原图等比适配正文宽度，避免无 DPI 图像超出纸面。

默认不为每批、每个边界都另开一次 LLM 审查。程序检查失败、编译出错或续接冲突时，只把具体问题及相关片段交给 LLM 局部处理；已通过且未受影响的批次复用。用户选择 `review_mode=all` 时，每批才增加一次独立审查，审查者同时看原图和转换结果，不重复进行“独立转录 → 再对照”的流程。

同次编译发现的、可分别定位的缺字问题按已有并发设置修复，各模型只获得本批错误；存在环境依赖的修复仍按顺序处理。每个修复结果返回后立即保存，恢复合并时以相同 S6 输入哈希校验并复用。

修复后重做受影响的检查；每批默认最多追加两轮完成的自动修正，仍失败就暂停并保留结果和原因。用户手动恢复时，为所选范围内已耗尽的批次追加两轮机会；已通过批次默认复用，累计修正次数、请求记录和用量不清零。上游确认中断且没有返回候选的调用占实际用量，但恢复该内容修正轮次，且只恢复一次。鉴权或额度错误直接报告；提交结果未知时先查询或恢复原请求，不能盲目重复提交。

交付包含 TeX 工程、编译结果、未解决问题和实际用量，并注明是否做了逐批独立审查。编译通过不等于数学内容已经完全核对。默认模式仍可能留下程序无法发现的语义错误，真实测试需查看输出质量，不能以 block 覆盖率替代保真结论。

## 正常路径的消耗

45 页论文、每批 2 页，会产生 23 个转换任务，与 MinerU 的解析提交次数无关。正常基础路径为一次类型策略、一次全书设置和每批一次转换；邻页查询、局部修正和可选独立审查按实际发生情况另外计量。

首先用真实结果判断转换质量、耗时和用量，再调整每批页数与并发。应用不按 token 容量拦截任务，也不以装满模型上下文为目标。
