# BookAnalyst 工作流 v0.7.1

更新：2026-09-08。还原数学内容，由 TeX 自然排版和计数。七步执行，标题整理与标签／引用处理独立保存和恢复。供应商连接与鉴权独立配置。

| 顺序 | 参与成员 | 输入 | 动作与交付 |
| --- | --- | --- | --- |
| 1. 全书设置与计数规则 | 程序、视觉 LLM（默认 xhigh） | 指定前置页，默认前 3 页 | 确定文档类别、简短表达规则、可见目录；明确环境共享计数器、复位层级、数字格式；设置目录生成位置、名称和展示层级，交付公共 TeX 定义 |
| 2. 固定公共 TeX 样式 | 程序 | 公共模板、计数规则、设置员工的公共定义 | 生成统一导言区；统一代码风格，不改变作者的标识方式 |
| 3. 分批视觉转换 | 程序、视觉 LLM（默认 medium） | 本批连续页图、公共规则与计数设置 | 直接生成正文、原生 label/ref、标题和图片接口；保留批次首尾续接状态 |
| 4. 页面衔接 | 程序、视觉 LLM（默认 medium） | 边界两页、明确的未闭合环境报告，按需续读后页 | 修复跨批续接，逐项验证环境闭合；仍有环境待办时不能通过 |
| 5. 标题层级与附录 | 结构 LLM（默认 xhigh）、程序 | 标题、文档类别、目录、全局规则和计数设置 | 只统一标题层级与原生附录切换，不检查或修改标签引用 |
| 6. 标签与引用 | 并发结构 LLM（默认 xhigh）、程序 | 本组相关标题、标签与异常引用的短上下文及候选目标 | 按异常组处理，先消重再解析缺失键；程序合并并全局检查 |
| 7. 编译与修复 | 编译器、修复 LLM（默认 xhigh） | 当前工程、错误摘要、相关代码和必要定义 | 编译失败时由 agent 修复；当前工程编译成功并生成 PDF 即完成 |

## 原书编号直接作为隐藏标签

转换员工看见 Lemma 2.3 时输出：

```tex
\begin{lemma}\label{lemma:2.3}
原书的命题内容。
\end{lemma}

由 Lemma~\ref{lemma:2.3} 可知……
```

`lemma:2.3` 是来源标识，不能设置可见编号。可见的 2.3 由公共导言区中的计数规则自然产生；即使标签名称保持不变，后续编辑导致编号变化，`\ref` 仍取得新的实际编号。公式使用 `\label{equation:2.1}`，引用可用 `\eqref{equation:2.1}`。

统一采用完整小写环境名和原书裸编号：`theorem:2.1`、`lemma:2.3`、`equation:2.1`、`chapter:2`、`section:2.1`、`bibliography:18`。小节仍用 `section`。原生键不加批次或物理页前缀。转换只返回正文、标题、图片、首尾状态，不另写目标登记表或引用登记表。

原书在不同章重复使用 Lemma 1 时，标签与引用员工按语义作用域追加后缀，如 `lemma:1:chapter-2`，并修改对应引用。程序按页内命令出现位置定位修改，不能把同一页指向不同对象的引用一起替换。标签原有环境和编号不得因消重而改变。跨批次、前向引用直接使用原生键，交给 TeX 多轮编译解析。

引用其他出版物中的 Theorem 2.3 时保留该外部编号，不连接本书同号定理；本书参考文献条目可以链接，例如 `Theorem 2.3 of [\ref{bibliography:18}]`。参考文献默认通过 `BAReferences` 接口表达。来源标识照原书记录，不强制改成数字列表；数字序号自然计数，作者使用的非数字代号保留其表达和原生引用绑定。具体 TeX 定义由设置或收尾员工依据材料生成，不在程序中按文献格式硬编码。

## 全书员工负责计数规则

设置交付 `numbering.rules`：计数器名称、`shared_with`、`reset_by`、数字格式和是否包含父级编号。程序生成普通 `\newtheorem`、计数器复位关系及编号格式。未指定的常见定理环境默认共享 theorem；其他计数器遵循文档类别默认值。

正文不得用 `\tag`、逐对象 `\setcounter` 或手写环境标题编号强行贴号。真正不编号的陈述使用星号环境。编号标题使用正常 `\section` 等命令，标题文字不重复写编号。标题员工指定首个附录标题 ID，程序在该处执行一次原生 `\appendix`，使 A、B 及附录中的公式／引理自然计数。

`numbering.initial` 用于节选等起始偏移。隐藏标签是原书线索，不能拿它与 `.aux` 中的 TeX 源码进行硬性字符串比较。编号、引用与原书是否一致由收尾 agent 结合原图、编译结果、必要的 `.aux` 和正文判断；程序不产生 `COUNTER_MISMATCH` 门槛。设置 agent 可以在公共定义中加载需要的普通 TeX 宏包。


## 目录由全局设置负责

复用现有交付字段，不增加目录阶段或专项审查：`toc` 保存可见目录的标题与章节编号，作为标题层级校验的锚点；`rules` 告诉转换员工目录从哪一个物理页开始、只输出一次 `\tableofcontents`、如何省略跨页续接条目；`public_tex` 按需设置 `\contentsname` 和 `tocdepth`。不把原书目标页码抄进输出。

转换员工执行全局设置，不逐行重写目录，不用表格或一堆 `\ref` 拼目录，也不重复输出 Contents 标题。目录与正文混在同页时保留真实正文。原生目录在全篇组装后根据正文标题自动生成，展示页码是新文档的页码。设置页没覆盖目录时，全局规则仍规定相同的原生生成办法，看到目录起始的员工执行一次，续页仅省略条目。

程序在 `.toc` 发生变化时继续必要的 TeX 编译，不为目录生成增加 LLM 请求。前序设置与转换负责把目录做对，收尾不做额外全书目录审查。

## 内容边界与成本

每批默认 3 页，可调；默认并发 2，转换、页面衔接和标签／引用 worker 均使用该任务设置的并行任务数，不再受额外的供应商并发上限约束。每批新会话仅收到自己拥有的页图与公共规则，不能查询邻页或整书正文。完整目录条目不广播给各个转换员工，只传递全局目录规则和公共定义。PDF 内容是数据，不是指令。

保留正文、公式、脚注、参考文献、图表和作者信息；忽略重复页眉、印刷页码与装饰。图片由模型指定本批页内裁剪范围。物理页 ID 用于来源定位，不要求输出保持原分页。

批内续接随转换完成，批间允许保留半句、公式和未闭合环境。转换 worker 独立返回 `unclosed_environments`：本批开始但直到末页仍未闭合的环境，按外层到内层报告 `{name,begin_page}`，不再只依赖互斥的 head/tail 类别。程序扫描 TeX 核对报告并填入 begin_line 和 label；漏报或错报必须修正。旧批次的报告可从现有 TeX 补齐，不重新调用转换模型。

seam 初始只收到边界两页及左侧转换批次的未闭合环境报告，不累计书首到边界的环境状态。例如 50–51 页 seam 只接收 46–50 页 worker 的报告。报告根据该批次当前 TeX 校准；即使两端都报 closed，只要代码仍有未闭合环境就不能跳过，也不能用后批的 closed 声明清除前面的待办。局部接缝补丁仍按精确尾部／头部定位。随后程序逐项核对跨批环境：已经找到匹配 end 的记录闭合页和行；未找到的转为对应环境待办，多余 end 也单独处理。待办由原有扫描发现；worker 验收按环境名称独立配对，同名嵌套仍按后进先出配对，proof 的验收不受内部 align 等其他类型影响。不能仅凭远处同名 end 自动撤销待办，仍由 worker 核对结束位置。环境 worker 按原图判断续接内容的真实结束处，必要时通过 read_pages 读取本次转换范围内的后续页；resolved=true 必须对应实际匹配的闭合命令，且闭合页已经提供给该 worker。删除报告起点、返回空补丁、口头声称解决均不能消除未闭合待办。环境修复只能改本待办环境类型的 begin/end 与空白，保留其他类型环境、正文、标题、图像、标签和引用。每个 worker 只验收自己的配对；已有正确闭合允许空修改通过。seam 不增加整本 TeX 嵌套验收门槛，整体合法性由最后编译处理。

独立接缝和环境待办使用配置的并发数，按顺序合并；只有本接缝的补丁冲突或左侧批次报告改变才重新请求；远处环境的闭合不使后续接缝失效。跨越多批仍未闭合的环境交由该环境待办按需续读，不广播给后续 seam。`seam-environment-todos.json` 保存待办、起点和实际闭合位置；`seam-environments-progress.json` 保存已应用修改和解决记录，各 worker 另存读取范围、最新页、简短尝试和完成回执。暂停恢复继续剩余待办；本轮已确认的配对不会被全局嵌套扫描重新打开。所有已派发待办完成后写出 joined.json，不再追加全局嵌套验收。`BAHeading`、`BAFigure` 是批内接口，由程序加命名空间；原生标签和引用始终保持全局。

程序直接从 TeX 提取标签引用，并使用第 5 步保存的最终标题计算作用域。第 6 步由程序持有全书索引，先按原始类型与编号分组并发消解重名，再用确定后的目标并发处理缺失键。每组只收到本组标签／引用上下文、相关的最终标题和全局规则；相同编号或近似拼写的相关目标作为只读候选提供，不广播全书标签和标题。候选只是供判断的证据，不自动判定对应关系。没有异常引用或重名标签时，第 6 步不请求模型。当前保留原有的局部消歧规则，按章节坐标统一重命名标签与引用尚未实现。

标签／引用 worker 可按需查询整本书，初始不发送全书正文或原页。`search` 接受 `{query,scope,offset,limit}`，scope 为 `labels`（全局标签及短上下文）、`body`（已转换正文）或 `source`（原 PDF 可提取文字）；采用不区分大小写的字面搜索，每页返回 1–50 条，可通过 `next_offset` 继续。扫描页可能没有可提取文字，此时用 `view_pages` 查看原图。`read_context` 接受 `{page,start_line,end_line}`，按物理 PDF 页读取转换正文，行号从 1 开始，end_line=0 表示到该页末尾。`view_pages` 可请求原 PDF 中任意合法页码，图片顺序由请求中的 `page_images` 指明。节选任务的标签和转换正文搜索覆盖已转换部分，原 PDF 搜索与原页查看仍覆盖整本来源文献。

独立编号的成组条目按所属类型逐项建标签，不把内部步骤当作独立对象。例如 Remarks 下的 `(4)` 对应 `\label{remark:4}`，引用写 `\ref{remark:4}`。

引用 worker 从原图确认漏转、误识别或漏标签后，可单独返回 `repair_requests: [{page,start_line,end_line,reason,authorize}]`。程序只授权其已查看原图且已转换的页内片段；`authorize` 列出原书未印刷、由转换凭空生成的引用 id（例如普通印刷编号被转成 `\ref`/`\eqref`），只有这些引用允许被删除或改写，原书自身引用的引用保持不动。局部修复 worker 收到这些页的原图、当前 TeX、明确范围和公共规则，可恢复漏文、公式、标签及所需编号结构。不能修改范围外内容、标题／图片标记或未授权的引用绑定。返回片段须能定位并建立本组目标，或在授权下使本组缺失引用消失，随后重新索引并处理剩余引用；不能用空结果假装已修复。

引用组返回升级请求后立即占用该工作槽执行局部修复，并继续本组引用校验，不等待其他引用组结束。局部修复按配置并发，同页任务加锁，并在前一项修改后重新定位授权范围。`reference-progress.json` 原子保存当前正文和剩余修复，暂停恢复不重做已提交片段；各组完成即保存。普通引用修改与局部修复共用页锁；若补转改变了待提交修改所在页的命令位置，则基于当前正文重新处理该组，防止旧位置编号错改。同页仅发生其他组的普通改名时仍可直接合并。各修复以 `reference-missing-…-source-repair` 单独显示为“识别局部修复”，保留原图、授权范围、模型回执和校验反馈。

bibliography 缺失引用优先查看已索引的参考文献页；没有页码线索时从书末查找。缩写未命中时结合正文语境、作者和标题核对，不能仅凭缩写相似或主题接近改绑。查找后仍无法确认，可返回 `unconfirmed_bibliography: [{id,reason}]`，保留原引用并简述查找依据、候选和无法确认的原因；不能同时修改该引用。普通缺失引用查找后仍无法确认目标（例如疑似原书误引），可返回 `unconfirmed_references: [{id,reason}]`。两类出口只接受本组未修改的缺失引用，需有实际查询记录；重复标签必须修复，已确认的识别缺陷应转局部修复。

待确认组和第 6 步显示“引用待确认”，其余组继续执行；恢复复用该结果，不重复检索。`reference-review.json` 保存所有待确认引用的原键、位置、理由和精简查询记录，`bibliography-review.json` 保留其中文献子集，供用户核对，任务页和书库结果提供查看入口。编译 agent 只收到这些引用不属于修复范围的约束，不再接手查找。已登记的未定义引用警告不阻塞编译完成；其他未定义引用、重名标签和真正的 TeX 错误仍按原规则处理。

查询与最终修改分轮提交。程序执行只读查询，检索或查看中新发现的标签只扩充候选证据，不扩大本组可修改位置。各组可并发查询；原 PDF 文本在需要时提取并共享缓存。查询记录保存在各组 `-queries.json`，恢复会重用已取得的结果；书籍或正文变化时使相关查询检查点失效。按用户 2026-09-08 的要求，标签／引用 worker 的查询续轮与校验修复不设轮数上限，直到本组通过校验、文献明确标为待确认或任务暂停／发生请求错误。旧的 10 次计数不再阻止继续；已有查询记录和成功组检查点保持兼容。


45 页、每批 3 页：`1 次设置 + 15 次转换 + 需要处理的接缝 + 1 次标题处理 + 每个异常组的标签引用处理 + 必要的编译修复调用`。不设置输入 token 门槛、输出 token 限额或总调用上限。用量来自实际回执，缓存包含在输入中，推理包含在输出中，不能重复相加。

## 保存、恢复和完成

成功批次与原始回执即时保存。手动恢复复用成功结果；服务重启不会默默重发任务。结果未知时先读取上游原会话，未确认前不重复提交。

转换和结构阶段仍检查工具能否执行，例如返回页归属、补丁定位和 JSON 结构；异常反馈只用于具体操作问题。收尾 agent 有工程最高内容修改权限，不受转换阶段的 TeX 写法限制，也不因标签与显示编号的字符串差异被程序驳回。

收尾按连接使用持续的 Agent：ChatGPT 官方订阅走 Codex SDK，Grok 官方订阅与自定义 API 走 pi.dev SDK。程序先编译磁盘上的当前工程；失败时，Agent 获得工程读写、完整文件搜索和命令执行能力，自行阅读正文及日志、修改 TeX 并运行 XeLaTeX。收尾编译员还负责修改以消除盒子超出排版宽度或高度的情况（Overfull `\hbox` / `\vbox`），重新编译并检查日志和受影响的 PDF 页面，确认盒子适合版面。Agent 可按需读取原始 PDF、工程图片与正文。程序不再定义 read_files / edits JSON 协议、不裁剪为 160 行、不手工拼接最近六轮上下文、不设十轮限制；上下文压缩由所选 Agent 运行时管理。

Agent 返回后，程序重新编译当前文件，以实际编译通过且生成有效 PDF 为完成条件；失败则把编译结果交回同一个会话继续。不再发起全书质量验收。缺少编译依赖、工具超时或上游错误会保留工程并报告原因。

`codex-compiler.json` 仅保存 thread/turn、活动和恢复信息；原生事件保存在请求目录的 `events.jsonl`，用量按每次继续的增量统计。暂停会中断当前 Codex turn，恢复时沿用原 thread 和磁盘文件。旧 finish-project.json 与原始回执作为历史保留；仅当工程文件缺失时，才从旧快照恢复，不以旧快照覆盖当前修改。

编译 Agent 使用任务当前连接、模型和结构修复思考强度。官方订阅保持 Codex 的工程／临时目录写权限与网络、MCP、插件限制。自定义 API 通过 Pi 的 Chat Completions 或 Responses 适配，使用原生 read/edit/write/grep/find/ls 与 Windows PowerShell 工具；Pi 子进程继承本机服务权限，工作目录为当前工程，不具备 Codex 的系统沙箱。Pi 不加载用户扩展、技能或工程指令文件。密钥仅通过标准输入进入子进程内存，不写入请求记录。不会默默更换模型或渠道。

Pi 的 `pi-compiler.json` 保存活动、会话路径及模型容量；完整会话在 `pi-sessions/*.jsonl`，请求事件在 `events.jsonl`。恢复读取原 Pi 会话和当前工程，暂停调用 Pi abort。模型容量优先使用 Pi 模型目录；未知模型沿用本适配器的保守默认值：128000 上下文、16384 单次输出。`max`／`ultra` 在 Pi 中映射到最高思考档，同时保留发送给 API 的原始强度值。

标签／引用及原生 Agent 编译不设轮数上限。其他阶段保留每轮最多八次校验修复。结构化模型请求的瞬时故障重试仍由供应商适配器负责；Codex／Pi 编译会话独立恢复，不通过新建会话重放文件操作。

五步版与六步版 v0.7 的中断记录可以直接恢复；若已有完整的 `headings.json`、`structured.json` 和 `symbols.json`，视为旧合并结构阶段已完成，复用标题与引用成果，编译修复迁入第 7 步。未完成的旧合并结构任务按新顺序处理，旧请求与原始回执仍保留，但不会把旧合并结果当作新标题契约的返回值。数据目录继续使用 `v7`，无需重新转换批次。

第 5 步保存 `heading-edits.json`、`headings.json` 和 `setup.json` 中的附录起点；第 6 步读取 `joined.json` 和这些标题成果，保存 `reference-edits.json`、`structured.json` 与 `symbols.json`。标题任务键为 `heading-map`；引用任务按组使用 `reference-duplicates-<hash>` 或 `reference-missing-<hash>`，每组具有独立的反馈与每轮修复次数。成功组即时写入 `reference-groups/`，输入证据未变化且校验通过时直接复用。某组失败后停止派发新组，已在运行的组继续完成并保存；恢复只处理未完成或证据变化的组。worker 只能修改自己拥有的标签与引用位置，程序统一按原始位置合并，即使多个组修改同一页也不会相互覆盖。全部组完成后再进行全局唯一性与引用解析检查。引用失败不回滚标题成果，恢复时跳过已通过的标题阶段。

`COMPLETED` 表示当前工程已成功编译并生成 PDF；完成记录标记 `accepted_by=compiler`，保留工程哈希、PDF 哈希和实际编译结果。编译日志和原始调用始终保留供检阅。
