# BookAnalyst 工作流 v0.6：视觉独立转换

更新：2026-09-06。状态：新版设计，待实现与真实验证。当前运行服务仍为 v0.5；本文件不代表已经完成执行器迁移。

目标：忠于作者的数学表达、内容、编号和标题架构，交由 TeX 重新排版。主流程不使用 MinerU，不恢复原页码、页眉或版面。供应商连接、模型和思考强度属于独立配置，不增加业务阶段。

## 五步工作流

| 顺序 | 执行成员 | 可见输入 | 动作与输出 |
| --- | --- | --- | --- |
| 1. 全书设置 | 程序准备材料；分析 LLM 判断 | 指定的前置页图、可用的 PDF 书签和目录页 | 确定文档类别、标题与作者编号偏好，输出简短设置。目录单独保存，供第五步使用。 |
| 2. 固定公共 TeX 样式 | 程序 | 全书设置、项目统一模板 | 固定公共导言区、环境与标题接口。各批只收到简短使用约定，不各自设计样式。 |
| 3. 按页分批视觉独立转换 | 程序分配；视觉转换 agent 并行执行 | 本批连续几页的原图、公共约定、简短设置 | 在同一任务内识别并生成 TeX；保存正文片段、页级定位和首尾续接标记。 |
| 4. 按衔接点处理页面衔接 | 程序合并；衔接 LLM 只处理不能直接接合的边界 | 上一批尾部、下一批头部，以及这两页的原图；必要的继承环境状态 | 接续断句、跨页公式、证明和数学环境；仅返回接缝补丁。 |
| 5. 修复标题层级 | 程序汇总与应用；标题 LLM 统一判断 | 按原文顺序的标题清单、作者编号、已有目录；仅冲突处补充页图 | 返回标题 ID 到层级的映射及必要标题修正。程序应用、编译并导出 TeX 工程和 PDF。 |

PDF 登记、渲染、调度、保存和编译都是程序动作，不各自增加 LLM 阶段。

## 1. 全书设置

程序优先使用现有书签定位目录，或使用用户指定的目录页。没有定位信息时，先准备开头少量页图；设置不足时使用固定模板和作者显式编号，允许进入转换，不为获得完整设置扫描整本书。

全书设置只决定整体表达约定，标题层级可在最后修正。目录识别不完整时明确保存其覆盖范围；不能据此删除正文中额外出现的标题。前置页面范围可调整，追加读取照实计入调用。正文、图表、脚注、参考文献及作者信息属于内容；印刷页码、重复页眉和纯装饰不进入正文。

## 2. 公共样式

由程序提供固定的数学宏包、常用环境与标题接口。作者的定理、公式等编号显式保留，避免批次独立计数导致漂移。转换 agent 输出正文 TeX，不输出完整文档或重新定义公共宏。

普通 LaTeX 数学命令交由 TeX 处理，不再因程序未登记某个正常命令就请求重写数学表达。编译使用固定环境并关闭 shell escape；公共样式统一不等于复刻原书排版。

## 3. 页面所有权、访问边界与交付

程序按 `pages_per_task` 切成连续且不重叠的批次，按 `llm_concurrency` 并行派发。例如每批 3 页：1–3、4–6、7–9。批内页面之间的衔接由同一个转换 agent 完成，批间衔接留到第四步。

每批启动独立会话。转换 agent 能看到的书籍内容严格限于本批页图；可以放大或裁剪这些页，不能查询邻页、读取完整 PDF、其他任务目录、已有转换结果或整书目录。共享设置只包含表达规则，不包含其他页的正文。

页面隔离由程序的访问边界落实：任务材料只含本批渲染图，图像读取与裁剪工具只能接受本批页 ID，输出工具只能写本批结果。模型可调用的工具不得具有任意文件读取、通用 shell、联网检索或委派能力。若采用允许文件操作的 Codex agent，必须另行使用能够限制读取范围的运行环境，并验证完整 PDF 和其他批次不可访问；隔离未实现前，不能把普通只读会话宣称为严格页面隔离。供应商通信和凭据由宿主适配器管理，不作为模型工具开放。

Codex 官方文档中，`read-only` 是只读权限模式，不是“只许读取当前几页”的定义。因此仅指定工作目录、只读模式或写一条提示词，都不足以证明满足本项目的页面边界。[官方沙箱说明](https://learn.chatgpt.com/docs/sandboxing)

输出以 `body.tex` 为主，附带最少的结构信息：

- 原始物理页到正文位置的标记，由程序验证页 ID，再提取页级来源映射。
- 带稳定 ID 的标题接口，便于最后只修改标题层级。
- 批次开头和结尾是否承接段落、公式或环境；不能确定时用一个简短状态标记，不写疑点报告。

不输出逐 block 的重型 JSON，不复制原文作为纠错前值，不要求逐处证明 OCR 修正，不生成自我审查长文。原图无法辨认的具体内容就在片段对应位置标记，不能凭数学常识补写。图表需要保留为图片时，agent 指定本批页内裁剪区域，由程序生成资源。

允许批次以半句、部分公式或尚未闭合的环境结束。页面边界不意味着环境结束，不要求每批单独编译通过，也不为独立编译填补原文不存在的内容。

## 4. 接缝处理

程序按页序拼接所有批次，并逐个处理相邻批次的接缝。首尾标记一致且 TeX 结构能够直接续接时直接合并；断词含义、部分公式、重复开闭环境或首尾状态冲突需要判断时，才交给衔接 LLM。不能仅凭编译通过认定语义衔接正确。

衔接任务默认只收到上一批末页和下一批首页的图像、对应首尾片段，以及程序沿原文顺序维护的环境栈。长证明跨过多个批次时，继承状态可以来自更早的已合并片段，不反复附带整个证明；片段本身无法确定环境时保留未决状态，交给相连边界一起处理。

补丁只允许修改指定接缝范围，不能重写完整批次或正文论证。不相交接缝可并行；若两处修改范围重叠，程序合并为一次局部任务或按序应用，避免覆盖更新。原始转换结果保留，续接结果单独保存。

## 5. 标题层级与最终编译

转换阶段顺带识别标题并保留作者编号；程序从结果中提取标题列表，标题 LLM 集中修正层级，不重新阅读全书正文。原目录是校验锚点，不以 TeX 字符串完全一致作为通过条件；同义的数学写法不能造成无限目录匹配失败。

标题补丁限定于标题命令、层级和确有原图依据的标题文字，不能重新编号数学环境、移动正文或改写公式。没有目录时依据标题顺序、编号和全书规则判断，不能发明未出现的章节。长书标题表必要时按最高层级拆分处理，不把正文拼入标题请求。

程序完成合并和标题更新后统一编译。实际编译错误只回送错误位置及必要原图，修正后继续编译；不为每批固定添加独立审查。不重复调用“转换—审查—改写”直至满足无关格式要求。

## 用量与恢复

每批页数控制输入规模；应用不设置上下文 token 门槛或输出 token 上限。模型与思考强度可配置，不能把 agent 内部多轮调用隐藏成“一次请求”。统计区分业务任务数、应用层请求数、可获得的上游实际输入/输出/推理 token 和耗时；无法取得的实际用量标为未知。

45 页、每批 3 页时有 15 个转换任务。若全书设置和标题处理各一个任务，业务任务数为 **17 + 实际衔接任务数 + 实际异常修复任务数**。这不是保证的模型推理次数或 token 预算；agent 工具往返和内部推理仍有成本。成本改善必须与同一份真实文献的旧流程结果比较。

成功批次即时保存，重试只处理失败或受影响部分。自动修复仍需有限停止条件，手动恢复可继续；历史用量不清零。未知上游请求先恢复原结果，不盲目重发。无需因为版本升级重新解析原书，但 v0.5 的 MinerU block 校验结果不冒充 v0.6 的视觉转换证据。

## 实现与验收范围

现有 v0.5 的 PDF 渲染、供应商连接、并行队列、保存恢复、编译和用量记录可复用。v0.6 需替换转换输入输出、实现任务材料隔离、接缝补丁及标题映射，并移除主路径的 MinerU/type 过滤、邻页查询、逐 block 覆盖与变更登记关卡。

真实验证使用用户已授权的文献，核对数学内容与普通作者内容的遗漏、接缝效果、标题层级、实际耗时和用量。页级来源映射只证明页面归属，不能自动证明页面内文字无遗漏。隔离测试必须验证跨任务读取被拒绝。以上尚未实施，不能用旧版整篇跑通记录证明新版成功或更省 token。
