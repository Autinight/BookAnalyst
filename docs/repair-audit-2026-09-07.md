# 139 页任务反复修复审计

2026-09-07，任务 `0f178bb78d584506885c94512e076714`，Atiyah–Macdonald《Introduction to Commutative Algebra》。依据本地原始请求、响应、编译回执及代码，未新增上游调用。

## 结论和账目

反复修复主要由程序的错误硬门槛引发，不能归因于模型不认识带撇号的编号。70 次调用中：设置 1 次、转换 35 次（28 批及 7 次返修）、衔接 13 次、结构 1 次、收尾 20 次。

| 部分 | 请求次数 | 真实原因 |
| --- | ---: | --- |
| 转换返修 | 7 | ASCII 标签白名单拒绝 `4′`、`5′`、`2.12*` 等原书标识；属于程序误拒 |
| 收尾前四次 | 4 | 两次补充上下文、两次实质修改，解决缺少 `mathrsfs`、未闭合环境和原书计数规则缺失；存在真实工程问题 |
| 收尾后十六次 | 16 | 同一组带撇号的编号被重复报为 `null` 或字符串不一致，诱发来回改写，期间又产生缺字和 TeX 语法错误；根因是程序误判 |

最后 16 次共 1,738,322 token，20 次收尾共 1,978,498 token，全部来自实际回执。缓存已包含在输入、推理已包含在输出，未重复相加。后期每轮反复携带约 21 张原页图和大段旧文件内容，单轮输入达到约 10.6 万 token，放大了错误循环的成本。

设置 agent 只收到前三张前置页，没有编号数学内容，故 `numbering.rules=[]`。原书章节复位、习题独立计数和特殊序号留到了收尾才补齐，属于全局设置阶段的输入不足。不能要求模型凭封面猜出全书规则。

## 错误门槛如何形成

旧 `numbering_report` 用不支持嵌套大括号的正则读取 `.aux`。例如 `\newlabel{equation:4′}{{{4'}}...}` 明明已有编号，程序却报 `rendered: null`；即便读取成功，也会把 `4$'$` 与 `4′` 当成不同编号。随后 `COUNTER_MISMATCH` 被作为“必须返修、不得完成”的条件，而非给 agent 的可疑线索。agent 没有自行验收的出口。

初步定位工具不应冒充确定的数学判定。发现计数偏移是需求，强行把原始 TeX 写法等同于显示结果不是需求。

## 已改的职责

- 删除自动编号字符串比较及其 `COUNTER_MISMATCH` 验收分支，未继续扩充自制编号解析／渲染校验器。
- 收尾 agent 读取原图、工程、编译日志、`.aux` 与输出 PDF 页图，自主修改、调用编译并明确 `accept`；程序执行工具并记录验收，不做第二次数学裁决。
- 设置 agent 可加载普通 TeX 宏包；不再把“固定公共样式”解释为禁止所需宏包。
- 长文本和旧页图保留到本次修改完成，不再永久累积进每个后续请求。
- 用户新要求的 10 次上限按处理单元持久保存；收尾包含工具与验收轮次，达到上限仍未验收时报 `REPAIR_LIMIT`。旧三次相同结果门槛取消。

## 哪些检查有依据

| 检查或规则 | 依据和职责 |
| --- | --- |
| 转换只取得分配页、保留内容和来源接口 | 用户要求；返回页范围和接口完整性由程序检查 |
| 自然计数、原书编号及引用正确 | 用户要求；由全局设置与收尾 agent 根据原图和编译结果判断 |
| 能否读取文件、页码有效、精确补丁能否执行、返回 JSON 有效 | 工具执行条件；不等于内容不正确 |
| 工程内读写、文献不能访问账号或任意执行系统命令 | 执行边界；不限制 agent 选择普通数学 TeX 写法 |
| ASCII 编号、把 TeX 源码当显示编号比较 | 无用户依据，已移除 |
| 自动修复最多 10 次 | 用户本轮明确要求，已实现 |

## 后续纠正：手动继续

上述停机处理把自动修复上限错误地当成了累计永久上限。用户明确要求：点“继续”必须能继续。现改为每轮最多 10 次，手动开始／恢复开启下一轮；服务重启或重复提交同一次操作不会刷新次数。历史请求、用量及已完成工程保留。回归测试覆盖旧任务已有 10 次和 20 次请求后继续执行、再次到限、重复点击与重启恢复。
