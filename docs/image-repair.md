# 独立图片修复

左侧“图片修复”标签页用于已保留到书库的转换结果；书库中的“修图片”也可直接进入。

1. 选择书籍，勾选要检查的图片，点击“检查并修复所选图片”。
2. 使用模型设置中独立的“图片修复”连接、模型及思考强度，逐图发送原页、当前裁图和附近 TeX。可选择与正文转换不同的视觉模型，检查和新裁图复核都使用此配置。
3. 模型判断当前裁图是否完整；需要重裁时返回原页归一化坐标，程序从原页重新截取（不是在旧裁图上继续裁），再把实际新裁图交给模型复核。模型也可独立设置插入宽度。复核未通过或无法确认时，原裁图和插入宽度都不变，并显示具体理由；其他图片继续。
4. 本轮结束后集中编译并保留新版。原结果目录不覆盖；若书库已在此期间产生更新结果，不自动替换它，修图输出仍可从任务下载。

支持暂停、继续及查看原页／修复前／当前裁图。任务出现在运行记录中，打开后回到图片修复标签页。已完成表示本轮处理和编译成功，待确认图片仍单独显示，不表示全书视觉验收通过。

图片修复有独立的默认并发；创建任务时可用“本次修图并发”覆盖，不修改正文转换或其他任务。未完成的任务点击“更新模型与并发”后，后续请求使用设置页已保存的修图模型及当前输入的并发；已发出的请求不取消，已完成的图片不重查。想用新模型重新检查已完成的图片，请从书库当前结果新建修图任务。

旧设置初次显示时以原转换配置作为修图配置的初始值，保存后独立维护。已有修图任务保持原冻结配置，直到显式更新。

主流程仍为原来的七步，不增加图片验收阶段。生成工程仅额外保存 `image-assets.json`（图片 ID、原 PDF 页码、裁剪框、文件路径、DPI 和来源 PDF 标识；修图后还记录显式插入宽度 `width_ratio`）。旧书可从原转换批次及模板任务来源恢复记录；没有来源的图片会显示原因，不自动猜测。

模型仍只用 `keep / recrop / uncertain` 三种判断，不增加操作分类。`bbox` 为整张原页的 `[left, top, right, bottom]`，左上角为原点，范围 0–1；仅 `recrop` 使用。`width_ratio` 为可用正文宽度的比例，范围 `(0,1]`，例如 `0.5` 表示半宽，`null` 保持现有尺寸。`keep` 可同时设置宽度，`recrop` 可同时设置裁剪框和宽度；`uncertain` 不应用任何参数。重裁复核只确认实际裁图内容，不声称已核验排版尺寸，也不增加逐图编译。

图片任务在独立工程副本上操作，不改正文和图注。显式宽度只改对应图片的插入命令（标准 `\BAFigure{id}` 或直接 `\includegraphics{assets/id.png}`），生成带宽度参数的 `\includegraphics`，保留图片 ID、来源和其他图片设置。宽度以当地 `\linewidth` 计算，保持长宽比，高度最多为正文高度的 80%；PNG 像素不因插入尺寸改变而重采样。旧版固定正文宽度的标准图片宏仍会更新为只缩不放，缺失的裁图 DPI 按原转换分辨率补齐。自定义模板宏本身不变，明确设置宽度的图片使用新参数。不做版面还原、漏图全书扫描或额外编译代理修复。

接口：`GET /api/books/{id}/images` 查询可修图片；`POST /api/books/{id}/repair-images` 使用当前结果 ID、图片 ID 列表及操作 ID 创建任务；`GET /api/runs/{id}/images` 查询逐图状态。暂停／继续复用原运行操作接口。
